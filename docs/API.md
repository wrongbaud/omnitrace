# API reference and header reading order

This page is for someone who is about to call or extend the OmniTrace library
from C++ and wants to know which header to open first. After reading it you
can build the browsable API reference, read the twenty public headers in an
order where each one only uses what the previous ones introduced, and find
the implementation, tests and format notes behind any type. The headers under
`include/omnitrace/` are the contract (`docs/ARCHITECTURE.md`); their Doxygen
comments are the authoritative description of what each type does today.

## Building the API docs

The reference is generated by Doxygen from the headers and `README.md`.
`Doxyfile` at the repository root is already configured: input is `include`
and `README.md`, undocumented public members are warnings (not errors), no
LaTeX, no graphs, so no `dot` is needed.

```sh
# Arch: pacman -S doxygen   Debian/Ubuntu: apt install doxygen   macOS: brew install doxygen
cd /home/wrongbaud/projects/omnitrace-v2
doxygen Doxyfile
xdg-open build/doxygen/index.html      # macOS: open build/doxygen/index.html
```

`build/` is git-ignored, so the output never lands in a commit. A warning
about an undocumented member is a defect in the header, not in Doxygen: fix
it by adding a `///` comment (the style rules are in the next section).

You do not need Doxygen to read the API. Every header opens with a `// File.h
— ...` comment saying what it is for, followed by a `/// @file` block with the
ownership, thread-safety and error rules for everything in it.

### Comment conventions in the headers

| Convention | Meaning |
|---|---|
| `/// text` before a declaration | Its documentation; the first sentence is the brief (`JAVADOC_AUTOBRIEF`). |
| `///< text` after a field or enumerator | Same, for one-line members. |
| `@param` / `@return` | Only where the name does not already say it. |
| `` ```cpp `` block | A short usage example; the four types you meet first (`Span`, `Sink`, `FilesystemReader`, `Validator`) each have one. |
| "Stable code" | A kebab-case string in `Status::error` or `Diagnostic::code` that tests and downstream agents match on; it never changes meaning once shipped. |

The remaining core headers are utilities you meet when you need them:
[`core/Compression.h`](../include/omnitrace/core/Compression.h) when a reader
decompresses a block, [`core/Swap.h`](../include/omnitrace/core/Swap.h) when a
dump has reversed words, [`core/Text.h`](../include/omnitrace/core/Text.h) when
an evidence string is about to leave the process,
[`core/Clock.h`](../include/omnitrace/core/Clock.h) only from the CLI.

Each layer is one static library built by `omnitrace_module()` in
`cmake/Warnings.cmake:22`, which globs `src/<layer>/**/*.cpp` and
`tests/unit/<layer>/**/*.cpp`; adding a file needs no CMake edit. Layer
dependencies are `apps/cli -> output, discovery, containers, images,
filesystems -> core` (`docs/ARCHITECTURE.md`). `src/images/` has no sources
yet, so `omnitrace::images` is an interface target.

## Rules you will see repeated in the headers

- **Ownership.** Sources are held by `std::shared_ptr<const Source>`. A
  `Span`, a `SubSource` and a `SwappedSource` each keep one, so bytes stay
  mapped while anything can still read them. A `std::span` from `Span::view`
  is valid only while that Source is alive.
- **Errors.** `Status` for an operation that fails as a whole, `std::optional`
  for a read or probe that yields nothing, `Diagnostic` for a degraded result
  that still produced data. Nothing throws on bad input; the one exception is
  `SignatureSet::builtin()`, which throws `std::logic_error` when the embedded
  TOML is broken, because that is a build defect.
- **Limits.** Every cap is a `Limits` field. A tripped cap stops that branch,
  records a `<fmt>-limit-<what>` diagnostic and keeps what was recovered.
- **Thread-safety.** The three registries (`ValidatorRegistry`,
  `FilesystemRegistry`, `ContainerRegistry`) and `SignatureSet::builtin()` are
  populated at static initialization and read-only afterwards, so lookups may
  run concurrently once `main()` has started. `Clock::set_override` and
  `Clock::now` share a mutex. Everything else (`Manifest`, a `Sink`, a reader
  instance, a `Hasher`) is single-threaded state.
- **Determinism.** No clock outside `Clock`, `std::map` instead of unordered
  containers in anything serialized, ids from insertion order. The same image
  and options give a byte-identical `INFO.yaml` apart from the run
  timestamps, `run.argv` and `evidence[].acquired_at` (`docs/CASE_LAYOUT.md`).

## Smallest end-to-end program

Everything the CLI does is reachable through public headers; `apps/cli/analyze_commands.cpp`
is a longer version of this.

```cpp
#include "omnitrace/core/Source.h"
#include "omnitrace/discovery/Recurse.h"
#include "omnitrace/filesystems/Filesystem.h"
#include "omnitrace/output/Yaml.h"

int main() {
    std::shared_ptr<omnitrace::MappedFile> file;
    if (auto st = omnitrace::MappedFile::open("router.bin", file); !st) return 1;

    omnitrace::discovery::AnalyzeOptions opts;
    opts.out_dir = "case-router";
    opts.open_reader = [](const std::string& format) {
        return omnitrace::fs::FilesystemRegistry::instance().create(format);
    };

    omnitrace::Manifest m;
    omnitrace::discovery::Listings listings;
    if (auto st = omnitrace::discovery::analyze(file, "router.bin", opts, m, listings); !st) return 1;

    std::string yaml = omnitrace::output::manifest_to_yaml(m);  // write as INFO.yaml
    return 0;
}
```

On the 16 MB OpenWrt image at `/home/wrongbaud/projects/omnitrace/firmware/router.bin`
this yields a uImage container at `0x50000`, a SquashFS filesystem at
`0x1c9245` (walked into `case-router/filesystems/<id>/files/`) and a JFFS2
filesystem at `0xc60000` (an `unsupported` coverage row until its reader
lands). The same run from the shell is
`build/linux-gcc/apps/cli/omnitrace analyze router.bin --out case-router`
(`docs/CLI.md`).
